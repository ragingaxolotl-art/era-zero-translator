# Stored-information deletion across sentences — November 22

Deletion previously worked mainly inside the requested-deletion construction. A new subject, an actual past action, or a second clause could fall back to the word picker. The shared sentence composer now handles **delete, deletes, deleted and deleting** with actor/target bindings, supported tense, possibility, ability, necessity, negation, questions, commands, conditions and ongoing aspect. For example, **We found the program. We deleted it** keeps the same program across both clauses.

This reuses the existing draft erasure structure: a transition whose result is non-retention of the selected information item in the contextual store. It adds no root, sound code, conventional compound or English dictionary entry. The 324 roots, 115 compounds and 574 senses remain unchanged. The earlier requested-deletion score bytes remain identical. The shared structure is now emitted and validated in both the dictionary-clause and whole-story routes.

The existing requested, ongoing and completed definitions remain distinct. A completed assertion is no longer labeled as a request. Future, possibility, negation and ability wrap the operation rather than changing its lexical definition. Runtime 0/1/2 remains a separate dimension. Deletion does not mean dormancy, hiding, moving, archival, forgetting, or guaranteed destruction of every copy. A named or potentially non-information target requires a focused meaning choice; every alternative target is checked.

They include different subjects/objects, role reversal, cross-clause pronouns, plural targets, conditions and commands. Rejecting the information sense does not enable Add to song. Editing the input clears stale controls. Playback buttons now have spacing and visible keyboard focus.
- **Two clean synthetic WAVs** recovered deletion with expected participants, time/negation/possibility and runtime 0/2. The isolated decoder received only the WAV and shared language definitions. This uses the existing experimental monophonic transport; it does not establish browser chord-audio or speaker-to-microphone recovery.
- The existing dictionary, physical-vocabulary and song regression suites pass. The older unsupported-song fixture now uses an actually unsupported word instead of the newly supported *deleted*. A clean run at `cdefd5f838e4ff81d14ab443e786d2ac30e6683a` passed all **262 implementation checks**; [results](information_erasure_2026_11_22/clean-regression.json) record the empty initial worktree and exact revision. All eight required [release gates](information_erasure_2026_11_22/release-gates.json), including the historical regression, also pass. Publication remains a separate check.

The parser still rejects unsupported passive/perfect deletion constructions, explicit source-store phrases, *only*, and causal subclauses instead of dropping them. Arbitrary storage systems, locations and retention policies are not introduced here. Copy, save, restore and remember remain separate work; none can honestly be added as an alias for delete. Existing saved songs and private definitions are preserved. The broader translator remains unfinished under the [completion plan](../docs/full-translator-next-steps.md).
