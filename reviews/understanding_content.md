# Draft understanding contract

The existing contextual-content selector is not itself comprehension. This
prerequisite separates the experiencer from the anchor of understood content and
adds an explicit comprehension criterion. It is a draft meaning document, not
canonical admission or a completed musical translation.

Bare “Eli understands Nora” requires a selected communicated-content, explanatory
reasons, or perspective reading. None is silently chosen from the name. Explicit
“Nora's communicated content”, “Nora's reasons”, and “Nora's perspective” select
those respective readings. Perspective comprehension does not entail sharing
feelings, agreeing, or approving; emotional empathy is not silently substituted.

The criteria preserve grasp of meaning rather than attention, receipt or
confidence. Communicated claims need not be true. Explanatory understanding is
relative to contextual explanatory adequacy, not mere memorization of words.
All content stays contextually selected; no specific message, explanation or
experience is invented. The matrix predicate is separately negatable and may
be questioned. Past placement and runtime 0/1/2 are independent.

The current parser deliberately rejects “what Nora said”: a complete treatment
must preserve the past communication reference, not erase “said” into a generic
content selector. It also rejects why-clauses, propositional factive understanding,
degree modifiers and plural/possessive pronoun constructions pending their
respective bindings.
These remain requirements, not exclusions from the final translator goal.

Validation includes 27 cross-products of content reading, runtime and
assertion/negated past/question forms, plus explicit selectors, contraction
equivalence, default draft rejection and rehashed semantic corruption.

The draft musical predicate now uses foundation code 3, following existing
desire, preference and polar-answer knowledge codes. Its definition digest includes
the three contextual adequacy criteria, and its content argument is explicitly
typed contextual_content. Existing roots and compound definitions are unchanged.
Existing role and scope frames bind the experiencer and selected content.

Twenty-seven MIDI-only inverse cases preserve reading, criterion, roles, scopes,
runtime and speech act. Three clean synthetic WAV cases recover those meanings
without source English or IR. The new lexical predicate event matches Ruby across
runtime 0/1/2. Full Ruby document validation and sentence rendering now match
29 browser MIDI cases, including alternate anchors and demonstrative references.
Default draft access and five rehashed corrupt semantic documents reject. Existing foundation
codec checks retain 972 old atomic performances.

The general translator now routes recognized understanding sentences to an
explicit draft card. Bare objects require a reading choice; explicit content
readings select their stated criterion. Preview offers music playback, MIDI and
the validated draft meaning document. Choice/source changes and late asynchronous
results cannot reuse stale outputs. Actual-handler tests use real composition,
export and MIDI inverse; live browser layout/listening is not yet verified.
The saved document is a standalone understanding draft, not the ordinary bundle
import format.

## Gender-neutral participant references

The understanding path now binds each he/she/him/her/it occurrence explicitly,
and supports singular they/them with an explicit `number: singular` choice and
referent. Pronouns are resolved into the same existing entity references; no
gender, animacy or identity is inferred from names. Twenty-seven contrasts show
identical meaning documents and MIDI for identical participants across he/she/they
wording, content reading and runtime. Reference identity, rather than English
pronoun spelling, determines the music. Quoted pronoun-like names remain labels.

The UI collects each referent and, for they/them, asks one individual versus a
group. Unknown number and plural selections reject explicitly; this is not plural
group support. Changing referents or number invalidates prior outputs. A complete
plural representation and discourse-wide antecedent tracking remain requirements.
The shared pronoun scanner's neutral-word option is now also used by desire,
preference, polar knowledge and learned-whether previews. A shared resolver
validates reference/number choices and snapshots strings before asynchronous
composition. Fifteen additional complete meaning/MIDI comparisons pass, and
actual-handler tests cover number fields and stale learning export rejection.
This does not claim they/them support throughout the entire translator.

The ordinary single-sentence pronoun path now also accepts singular they/them
with explicit number/reference fields. A shared substitution helper normalizes
supported English subject agreement (including present auxiliaries and inverted
questions) while preserving the chosen referent and predicate. Twenty-four
ordinary meaning/MIDI comparisons cover care, swimming, running, negation, time,
questions and speaker/addressee bindings. Existing thirty pronoun cases retain
Ruby parity. Actual UI-handler checks require number for both neutral references
and reject group coercion. This extends supported sentence forms; it does not
establish arbitrary pronoun grammar or discourse-wide antecedent resolution.
