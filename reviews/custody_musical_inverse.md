# Recovering custody meaning from music

`decodePhysicalCustodyMidi(bytes, atoms)` interprets the already approved convention
7 from strict MIDI plus the shared root sound inventory. It receives no English,
semantic IR, formal plan, compound graph or expected participants. The learned
convention supplies the lexical meaning, as a shared dictionary does for speech.
No encoder, root, compound definition or existing sound changes here.

## Recovered meaning and boundaries

The result identifies practical physical custody, holder and held object, outer
runtime state, ordered scope operators and speech act. References preserve audible
phonemes, nominal reference mode, instance code, deictic role or lexical identity
and its own runtime. Exact selected mass restrictions remain attached to the object.
The defined meaning is established practical control with a distinct object;
it requires neither exclusive control nor continuous physical influence and does
not assert ownership, receipt or transfer.

These commitments remain inside scope and speech act. Negated custody is not
flattened into active custody; a command does not assert an accomplished handover.
The decoder cannot establish external participant identity from matching labels.
Homophonic names remain indistinguishable unless the performance supplies a tag.
It reports a semantic projection rather than pretending to reconstruct original
English spelling or arbitrary graph node IDs.

The profile requires exactly source, qualified target and MAT:210 within convention
7, with their correct registers and state placement. It rejects another convention,
wrong roles, wrong qualifier/head roots, extra content and unsupported clause
combinations. Balanced musical frames alone do not prove a valid custody meaning.
General discourse, nested compound meaning, arbitrary audio and custody-transfer
interpretation remain unfinished.

## Shared parsing without weakening existing profiles

`strict_semantic_reader.mjs` factors the existing carrying inverse's strict tree,
reference, decimal, role and outer-scope reading. Carrying still enforces its own
conventions 3–6, exact event roots and repeated participant consistency; custody
enforces convention 7. Neither profile accepts another profile as a fallback.
The complete input must satisfy the selected profile.

## Evidence

The custody inverse suite checks 36 English sentence/state/scope/property cases
against manually specified semantic expectations and nine Ruby-generated
controlled speech-act/state performances. It checks octave transposition, holder/
object reversal, homophone limits, truncation and rejection of extra clauses.
An independent raw MIDI writer changes balanced convention, role, head and
qualifier tokens; these remain valid strict structure but must fail custody
interpretation. The carrying inverse's existing 36 sentence and six controlled
cases continue to pass after extracting the common reader. The complete current
regression run passes 83 checks.

This is a bounded independent semantic decoding milestone, not a listening test,
a new word, or completion of receipt/delivery. Next, define a transfer event with
one shared object, explicit before/after custody and the appropriate commitment
about whether the prior holder retains control. A sequence of custody statements
must not be silently promoted to that event.
