# Review: filling and emptying physical containers

This author semantic review continues the user-directed reusable vocabulary work. It is not independent linguistic validation or separate user approval of each meaning. Reuse the earlier physical capacity, full/empty states, and caused-displacement compound before introducing these result-changing verbs. No new atom is needed.

Both actions reuse **caused displacement in a physical frame** for the movement of contents. The outer target is the container; it is not the moved content. Filling uses the exact full-state dependency at its endpoint, and emptying uses the exact empty-state dependency. `ORI:110` actualizes that endpoint condition. Conventions 86 and 87 explicitly bind their phases and participants; root adjacency alone would not supply these relationships.

Filling reaches the same fixed contextual capacity threshold from below it. Emptying removes all contents that count under the same criterion from a previously nonempty container. Neither changes what counts midway through the event. Emptying is not negated filling, and partial removal is not completed emptying. Runtime 0/1/2 remains separate from content amount, time, completion and negation. Ongoing aspect does not assert that the endpoint was reached.

The existing adjective **empty** keeps its original meaning, identifier and music. The new verb sense has a separate identifier and an internal story key, **empty container**, so it cannot replace the existing adjective route. The public forms are empty/empties/emptied/emptying. Fill/fills/filled/filling uses the same sentence machinery. Both accept different actors and containers, questions, commands, scopes and clause relationships. Other uses of fill/empty require a physical-container choice.

The initial release leaves explicit content/source/destination phrases unsupported. **Fill the bottle with water**, **empty the box into the bin**, passive/perfect constructions and quantity restrictions need further grammar. A direct empty/full description on the changed container also needs a phase: **filled the empty box** describes an initial condition, while **the now-full box** describes a result. The current story-property representation does not identify that phase, so this batch must not silently claim to translate either attachment. Unchanging qualities on participants retain the existing behavior.

Before release: protect every previous dictionary/sense record; test state versus action, full versus nonempty and complete versus partial change; compare all runtime states and ordered scopes; preserve subject/object roles and supported modifiers; independently recover melody and chords; reject invalid participant bindings and altered nested definitions; verify browser ambiguity and unsupported-construction behavior. General microphone decoding remains outside this batch.
