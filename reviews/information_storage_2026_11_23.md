# Information retention, save and store

This author review continues the user-directed reusable vocabulary work. It is not independent linguistic validation or separate user approval of each definition. Existing roots and published definitions remain authoritative.

The stored-information state already exists as **DAT:000**, a persistent bounded information object maintained within one reference entity. The adjective **stored**, in the selected information sense, reuses that exact definition. It adds neither a saving event nor guaranteed durability, accessibility, truth or awareness. Physical warehousing and stored energy remain different readings. The past action **stored** and state **was stored** must remain distinct in ordinary sentence parsing.

The missing action is a bounded retention commitment. Convention 90 reuses DAT:000 for the retained record and ORI:110 for the completion of this operation's commitment. The target whose content is saved and the retained record are not required to be distinct tokens. An existing record can be refreshed or affirmed, including unchanged content. The actualized referent is the commitment for this operation, not necessarily a newly created datum or newly true storage state. This is an explicit conventional meaning; bare root adjacency would not establish the capture point or content-equivalence relation.

Convention 91 then adds the causally productive actor through ORI:211. This follows the dependency order: existing retained information → completed commitment → its actor. Save/saves/saved/saving and information-sense store/stores/stored/storing use this exact definition with an actor and target. An actor need not be a conscious person, and the meaning does not invent a gender.

The earlier copy compound requires a distinct newly generated result and preserves its source. Saving does not entail those conditions. DAT:100 would incorrectly require transformed information; DAT:110 would require transfer to a distinct target context. CRE:110 would require generated-artifact manifestation. Retention is also different from MIN-based memory retrieval and from physical placement. None of those neighboring words should be used as a save alias.

A save commits relevant target content at its capture point under a fixed contextual equivalence criterion. This does not promise exact bytes, metadata, a named destination, a new version, permanent preservation, power-loss safety or subsequent retrieval. Those need additional explicit meanings. Copying, sending and saving can overlap in a real operation, but none of those verbs silently entails all the others.

Information-target cues can select this reading for a file, record, program or document. Other labels need a focused information-versus-other sense choice. Selecting another sense must leave the sentence unresolved. The stored adjective must make the same distinction for states, noun descriptions and keep/stay conditions, including private words with the same label. Saved as a result adjective, destination and version complements, and passive/perfect event grammar remain separate work; inflected action forms must not smuggle them in as phonemic labels.

Before publication, preserve all earlier definitions, including the exact copy and recall compounds; freeze earlier information-operation sounds; check state/action and save/copy contrasts, actor/target identity, inflections, ordered scope, questions, commands and runtime 0/1/2. Independently decode ordinary and compact exports, reject malformed roles and sounds, and exercise the actual whole-sentence interface. Passing finite MIDI tests does not establish unrestricted English or general microphone decoding.
